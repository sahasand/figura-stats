# Sample size and power workspace

Audience: academic research including psychology, biomedical and clinical studies.
User request: a comprehensive, high-quality build, not a single calculator.

## Product contract

The `/sample-size/` module uses Figura's existing workbench: the shared toolbar,
analysis navigation, Configuration pane and paper-styled output. Its header and
navigation are derived from the main app during page generation. Study design
is selected within Configuration; results, sensitivity curves and saved scenarios
live in the output pane. It has no independent theme or landing-page header.
No dataset, account, cloud compute or language model is needed. Assumptions and
saved plans stay in the tab unless the user explicitly downloads them.

Each method states the estimand/test, assumptions, approximation and reference.
Every sample-size answer is an integer solution with achieved power recomputed
after rounding. Per-group, total, pairs, events and clusters are distinct units.
Attrition changes recruitment, never the analyzable sample used in power.
Edits immediately invalidate results and exports; stale asynchronous responses
must never replace results for a newer specification.

## Initial implemented catalogue

Independent, paired and one-sample means; balanced one-way ANOVA; Pearson
correlation; omnibus multiple regression; chi-square goodness of fit/association;
one and two proportions; continuous-outcome noninferiority and equivalence;
two-arm proportional-hazards survival; equal-size cluster-randomized continuous
outcomes; precision for a mean and a proportion. This is 15 method-specific
workflows. General mixed models, repeated-measures interactions, Bayesian and
adaptive designs require distinct validated models and are outside these methods.
The interface must not imply these are covered by an ordinary ANOVA or t-test.

Sample size, planned power and detectable effect are available where applicable;
precision methods solve sample size or planned interval half-width. Continuous
noninferiority/equivalence use an explicitly labelled normal approximation.
Cluster power uses cluster means and cluster-level degrees of freedom with fixed
equal cluster sizes. Survival reports events and uses an explicit expected event
fraction, not an invented accrual model. Wilson width is evaluated at the planning
proportion, not claimed to guarantee a realized width.

## Computation and evidence

R is the only statistical engine. Use CRAN `pwr` and R `stats`, with separately
documented formulae for margins, survival, clusters and precision. A dedicated
worker installs only jsonlite/pwr; it does not load the figure packages.
The engine must run identically in native R and webR. Export standalone R using
the actual engine functions, plus a JSON plan, CSV scenarios and printable report.

Reference tests cover published/package examples, noncentral-distribution values,
rounding minimality, unequal allocation, attrition, solver round trips, limiting
cases and invalid inputs. Numerical parity is evidence within the covered method,
not a claim that a user's design or assumptions are scientifically appropriate.

## Integration

The planner is a planning link, not another raw-data `data-figure` analysis.
Its index is generated by the existing page builder and included in the sitemap
and page navigation. Existing figures and user edits are preserved.
