Compared names the two artifacts behind the Figura and Python columns, in that order, because "Figura" is three different things depending on the tier. screen vs Python checks the numbers the user was actually shown against the independent implementation. exported script vs Python checks the harvest from re-running the .R the app exports — so a defect on that line indicts the export path, and says nothing against the displayed numbers unless a screen vs Python row fails too. screen vs exported script is Path A against itself: there the Python column holds the exported script's own value, not Path B's.

Coverage ("targets met") means every quantity the case declares in exact_targets was actually credited by a performed comparison — a coverage failure marks a case TARGETS UNMET even if every comparison that did run passed. NOT COMPARED marks a case that is registered and ran, but whose two paths were never set against each other; it carries no guarantee at all, and it is counted in the cases tile's denominator so the tile can never read complete while such a case exists. DEFERRED names declared coverage this run did not enforce because its comparison block has not landed yet — not checked, so neither met nor failed. “Targets met” and MISSING QUANTITY measure two different coverages, which is why a case can show both at once. “Targets met” — and the cases tile that counts it — is about the quantities a case declares in its exact_targets: every declared one was credited by a comparison that really ran. Missing quantity is about a quantity that was expected somewhere in the case and never compared at all, declared or not — the term the app displayed that the exported script never produced, say. A case can therefore meet every target it declared (green) while still publishing a MISSING QUANTITY row (red) for something outside that declared set. Both statements are true; read them as declared-target coverage and quantity coverage, not as one verdict contradicting itself. Display artifact means both paths computed the same number and only the rendered string differs, within half a display step. Defect means the values themselves disagree beyond a relative tolerance of 1e-6. Missing quantity means something expected was never compared at all — a coverage failure, not a value disagreement. Script divergence means the exported .R does not reproduce what the screen showed. Count mismatch means the two paths analysed different rows. Decision mismatch means the two paths chose different summary statistics for a Table 1 variable — mean ± SD where the other chose median (IQR), say — which is a defect even when every number in the row is individually correct. Diagnostic mismatch means the two paths disagree about whether one of the app's ADVISORY sentences — the C-statistic, VIF, EPV, Cook's-distance, separation or proportional-hazards note — fires at all. Those sentences never change a reported estimate, but they are printed for the user and pasted into a manuscript, so a disagreement about one is published like any other.

Published precision. The Figura and Python columns above are rounded to 9 significant digits for publication. The comparison itself ran at full double precision — the tolerances quoted above (relative 1e-6, absolute 1e-9) were applied to the unrounded values, which stay in the pipeline's own intermediate artifacts. So nothing here was judged at 9 digits; this page is simply not in the business of publishing the last four digits of a double, which differ between BLAS implementations and say nothing about the statistics.
